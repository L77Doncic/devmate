# 两级压缩：先截断/裁剪旧工具输出，必要时再整体摘要；只作用于投影

Claude Code 官方原话规定的顺序就是「先清更早的工具输出、必要时再概括对话」（"clears older tool outputs first, then summarizes the conversation if needed"，open-source-agent-architectures.md §2.3），而 mini-swe-agent 给出了第一级的工业参数：单条输出 10000 字符、头 5000 + 尾 5000、中间显式 elide 标记并附「怎么收窄命令」的行动指引——同时服务端 API 不截断工具结果（超限请求直接被拒），截断必须由客户端完成（context-and-error-handling.md §2.3，一手 YAML 已逐字核实）。DevMate 采用两级压缩——「三级瀑布」是它在实现侧的分层落地名：第 0 层生成期工具输出截断（10k 字符头尾保留）→ 第 1 层组包期工具结果裁剪（较早的工具结果按时间序替换为显式占位符、保留最近 3 组，副作用型工具结果豁免）→ 第 2 层触顶期对话摘要（五段式结构摘要压回稳定小体积，摘要提示词显式禁止模型调用工具）；每一层都只改写投影，append-only 事件流永远不动，摘要本身作为一条事件追加。顺序是硬性的：成本与信息损失沿同一方向递增——工具输出截断最便宜、损失局部化，对话摘要是一次完整采样的钱且有全局损失——先做便宜的一级能推迟昂贵的二级；占位符必须声明「这里曾有内容被移除」，绝不能装作不存在，否则模型会基于幻觉重建上下文（CONTEXT「占位符」词条）。

## Considered Options

- **单级摘要**：一次完整采样的钱 + 全局信息损失（早期指令直接消失是官方明说的；Anthropic 官方压缩可把近 100k 压回 2–3k，但代价与损失都大）；小任务本可在第一级就解决，单级摘要让「贵且有损」成为常态。
- **滑动窗口截断历史**：实现最便宜，但信息损失最大且无声——最早的任务描述/规则直接消失，且极易删掉 `assistant.tool_calls` 留下落单的 `tool` 消息（结果无请求；与领域正术语「悬空工具调用」——请求已落盘而缺结果——方向相反，但同为协议破坏），OpenAI 兼容端点直接 400（§2.1 对照表逐项标出协议破坏风险）——「最简单」伪装成「损失最小」。

## Consequences

- 具体数值（0.45/0.72 触发比例、keep=3、摘要目标 ≤8k、256KB 采集上限）单源化到 spec 参数表（§8 的 A-1/A-2，体系声明两套 tokenizer 常数体系不可混加）；窗口值未登记时不按比例做阈值计算，走「超限报错 → 压缩 → 重试（上限 2 次）」三层兜底（§1.4/§8B）。
- 压缩会失忆（官方承认早期细节丢失）：必须由每次会话开头注入的持久规则载体（CLAUDE.md/AGENTS.md 等价物，前 200 行或 25KB 先到为准）承接易失的规则与偏好。
- 摘要不收敛即熔断：连续 2 次压缩后在 5 分钟内（或 3 个轮次内）又触顶 → 停止自动摘要并显式报错——归 ADR-0006 的熔断信号。
- token 估算常数（Cookbook 值）落地前需以 tiktoken 离线标定（REVIEW.md C 表），标定前按偏高估算，避免触发阈值系统性提前。
