# 安全基线三层：工作区监狱 + 危险操作审批 + 沙箱/资源限制；无人值守靠隔离而非审批

审批流在无人值守（评测/CI）下要么阻塞要么被架空——Claude Code 自身演化出的 Auto 模式就是「后台分类器审查并拦截风险动作」而非逐条提问（open-source-agent-architectures.md §E），而字符串黑名单官方原话只是「a tripwire for obvious mistakes, not an enforcement boundary」，真正的控制是隔离（context-and-error-handling.md §6.1）。DevMate 决定安全基线三层互补：工作区监狱是模型行为约束层（启动目录为默认边界、额外目录显式登记、realpath 归一化后符号链接两端同检——allow 须两端命中、deny 任一命中即拦、`>`/`>>` 重定向目标按写入审查），管「模型放不放行」；危险操作审批是交互层（许可模式四档：Auto=后台分类器审查、风险项改拦截而非提问，Manual=改文件与 shell 全问，Accept Edits=自动接受常规文件改动，Plan=只探索不改源码；带备注拒绝拒因回注、无备注拒绝结束本轮），管「人与模型的交互」；沙箱与资源限制（命令在临时目录内执行、网络禁用、CPU/内存/磁盘 ulimit、日志审计、机密脱敏）是操作系统级隔离——无人值守时唯一真正可靠的防线，「无人值守靠隔离而非审批」。原因：三层都不是完备边界——监狱的判定恰好依赖「模型的决策」、提示注入能骗过它；审批在无人值守时失效；沙箱挡不住工作区内的合法破坏——必须叠加，且任何字符串黑名单类配置只是 tripwire，不作为安全边界。

## Considered Options

- **逐命令审批为默认**：交互模式可用且安全，但无人值守（评测/CI）无人在场——要么阻塞死、要么被全自动模式架空；且审批是「交互档位」（许可模式），不是规则来源，把它当默认等同于把无人值守场景排除在外（ARCH §E：mini 不给审批只给硬边界反而是安全做得最好的一条路）。
- **纯字符串黑名单**：官方定性就是 tripwire——可改写绕过（粘连写法、别名、包装器外命令）；更致命的是 runner 组合——`Bash(devbox run *)` 等于放行 `devbox run rm -rf .`；「识别所有危险命令」是不可完成的任务，黑名单只防常见错误、不构成边界。

## Consequences

- 只读命令白名单（只读命令免审批集合）是唯一免审批集合：判定前先做命令规则化——剥离包装器（timeout/time/nice/nohup/stdbuf/command/builtin）、复合命令逐段判定、重定向目标按写入对待、变量赋值前缀不得豁免 deny、「runner + 内部命令」（npx/docker exec/devbox run/mise exec/direnv exec）必须显式枚举组合（ARCH §G 第 7 条、context §6.2）；黑名单不作为配置形态。
- 与 ADR-0003 衔接：无人值守靠预算（成本护栏默认唯一开启的终止条件）与隔离双保险——预算管钱、沙箱管资源，二者互不替代。

> **注（2026-09-01 演进入库附记）**：本句「成本护栏默认唯一开启的终止条件」已被演进取代——护栏判据已改为 token、默认关闭、对话级（按会话经 composer 护栏 pill 设置，见 ADR-0003 文末「演进入库附记（2026-09-01）」）；隔离与预算双保险、二者互不替代的框架不变。
- 危险操作审批的拒绝走错误回注：带备注拒绝的拒因回注给模型继续工作、无备注拒绝才结束本轮（ARCH §D.2），与 ADR-0006 的轮次层错误处理分层完全一致。
- 工作区监狱是「模型放行」判定层，不替代 OS 级隔离：文件工具的越界防护在协议路线上先由结构化参数校验（spec F3 工具面，ADR-0008）承载、监狱兜底，回退解析路线（ADR-0011）则只剩监狱一层。
