# 终止条件以成本护栏为默认、步数为辅

> **注（2026-09-01 演进入库）**：本条标题所载「以成本护栏为默认」已被演进取代——护栏
> 判据现为对话级累计 tokens（Token 护栏）、默认关闭、按会话经 composer 护栏 pill 设置；
> 详见文末「演进入库附记（2026-09-01）」。正文保留历史裁决原文。

mini-swe-agent 的默认配置「不默认步数」是被逐字核实过的样本：`step_limit=0` 与 `wall_time_limit_seconds=0`（0＝不启用），真正生效的是 `cost_limit=3.0` 加连续 3 次格式错误熔断（open-source-agent-architectures.md §1.3，AgentConfig 数据类默认值；其 CLI 覆盖路径未核对，REVIEW.md B9 已标注）。DevMate 采用同一优先级：默认启用的终止条件是成本上限（成本护栏），评测基线 USD 3.0/任务；交互/web 模式成本上限跟随配置（缺省引擎 DEFAULT_COST_LIMIT_USD=$3.0；可经 settings 调高，为「上限」而非「无穷」），步数与墙钟上限默认禁用，仅评测/CI 给固定值（步数 200、墙钟 30 分钟，context-and-error-handling.md §8C）。原因是成本与失控的直接代价（账单）单调相关，步数不是：同样的 30 步可能完成任务也可能在兜圈子，而「钱」不依赖对模型意图的任何猜测——没有任何一家公开文档声称实现了语义级「兜圈子」检测，现有手段全是代理指标（ARCH §C.2），钱是最便宜、最普适的一个。

> 判据下依然成立（tokens 是账单与上下文失控的直接共同代价）。

## Considered Options

- **以步数上限为主**：把浪费变成「可预计上限」，但与账单无单调关系——刷步数的失败循环照烧钱，步数省下的钱不随步数变化；评测/CI 要公平比较时以固定步数/墙钟兜底即可（§8C）。
- **全自动无护栏**：交互模式至少用户随时可中断，但无人值守（评测/CI）没有 Ctrl-C——Claude Code 自己的演化（Auto 模式用后台分类器替代逐条提问）说明无人值守下审批流会被架空，最终只剩预算与隔离兜底（ARCH §E）。

## Consequences

- 保险丝必须前置在查询之前，且被计费的失败轮次也要补记成本（mini 的 `self.cost += …`），否则 ADR-0006 的错误回注自愈会变成绕过成本护栏的免费通道。
- 「成本超限同时是熔断与终止条件」（CONTEXT「成本护栏」词条，2026-09-01 起更名为「Token 护栏」——见文末附记；「终止与熔断合一」结构不变，被计费的失败轮补记对齐为补记 usage/tokens），与熔断机制不另设重复实现——可换的只是档位参数，这一「终止与熔断合一」的结构不可逆（与 ADR-0006 的耦合）。
- 成本核算公式需要五家单价表才能数值化——调研零价格数字（REVIEW.md D3.1），单价表补齐前闸门 A（请求前估价）只能以「本地估算 token × 占位价 + 手工任务预算」近似运行。

依据：open-source-agent-architectures.md §1.3（AgentConfig 默认值四字段）、§1.4（FormatError 补记成本与 finally 落盘）、§C.2 手法 1（「钱是最有效的全局护栏」——处理不终止风险的四种现实手法之一）；context-and-error-handling.md §5.1（保险丝优先级表）、§8C（成本/步数/墙钟参数表）、§4.1（E15 连续格式错误熔断）；REVIEW.md D3.1（单价表缺口）。

## 演进入库附记（2026-09-01）

本 ADR 的原始裁决以「成本（USD）= 默认开启的终止保险丝」为前提（mini-swe-agent 的
`cost_limit=3.0` 样本）。2026-08-31 用户定调后实现演进如下——**正文保留历史事实与
裁决原文，本条附记为现行口径**：

- **判据**：护栏从「美元成本上限」改为「对话级累计 tokens 上限（输入+输出之和）」——
  服务端 usage 真实值，无 usage 时本地估算；判据与单价无关（costUsd 统计照常显示，
  只统计、不参与护栏判据）。
- **默认关闭**：新会话/未设置 = 不限制（不再有「唯一默认开启的保险丝」；与
  subagentsEnabled 开关族一致：关 = 不拦）。正文中「默认 $3 保险丝」「默认唯一开启的
  终止条件」等句均为历史描述，已被本附记取代。
- **作用域与 UI**：按会话（每个对话独立设置所需上限）——UI 在 composer **护栏 pill**
  （不再入 settings / config.json，不放设置页）；发送经 POST /api/chat 的 `maxRunTokens`
  （正整数）透传，服务端校验（非法 400）、缺省 = 关闭；localStorage 按 sessionId 记忆。
- **结构不变**：「护栏命中同时是终止条件与熔断」的合一结构、保险丝前置在查询之前、
  被计费的失败轮补记（现为 usage/tokens）——与正文 Consequences 的框架一致。
- **实现**：`src/core/loop/agent.ts` 闸门 A（请求前 token 预判：累计 + 本轮 prompt 估算 +
  输出预留）/ B（流式中触顶即中止，尽力保留已生成部分）/ C（累计越限，下轮查询前停）；
  run-status 终态值仍为 `'cost-guard'`（状态值兼容测试/UI/历史），UI 文案
  「Token 护栏停机」（`format.js RUN_STATUS_SEMANTICS`）。
- **关联同步**：CONTEXT.md（终止条件/保险丝/Token 护栏词条与 Rules）、README 与
  README.zh-CN.md、deliverables/README.txt 均已随本演进改口径。
